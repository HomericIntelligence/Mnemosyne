# Verify Placement Authority — Case Notes

These notes hold the source evidence for
`verify-placement-authority-before-implementing-external-material.md`. All identifiers are
withheld under the privacy rules for stored lessons.

## Source session (generalized)

An automation session implemented an approved plan. The plan ported a provider control profile
from an external reviewed project into the distribution of a mechanism that consumes it. The
distribution owner rejected the premise: no content from the external project belongs in the
mechanism distribution. Nothing merged.

## Withdrawal sequence (verified)

1. The pull request closed with a comment that recorded the owner decision.
2. The head branch was deleted. A later reference check on the branch returned not found.
3. The issue closed with the same decision recorded.
4. The default branch stayed untouched. No open automation item remained for the rejected work.

## Retrieval evidence (bounded)

- A corpus selector listed the main skill files at the discovery revision. Intent groups
  inspected: issue-premise verification, cross-repo porting mechanics, external-pattern adoption
  into design plans, charter and scope audits, and authority checks for absent evidence. No entry
  owned placement authority for material bound to an external distribution.
- An open-pull-request scan at the delivery revision found seven open PRs. Each changed its own
  skill pair. None overlapped the intent.

## Deliberate omissions

Project names, repository names, issue and pull-request identifiers, internal paths, and verbatim
owner wording are omitted. They are not necessary for the reusable rule.
