# Prematerialize Git Objects Before Fail-Closed Verification

## Overview

| Field | Value |
| ------- | ------- |
| **Date** | 2026-10-27 |
| **Objective** | Make a fail-closed source verifier succeed on the first delivery run: complete the object store of the verification source before the verifier reads it. |
| **Outcome** | Successful. A terminal delivery that failed closed on an incomplete anchor source delivered after the missing lineages were fetched by object identifier and each bound record regenerated byte-exactly against the completed source. |
| **Verification** | verified-live in one delivery run: the immutable git reads failed closed against the incomplete clone, passed after fetch-by-identifier restoration, and each historical record matched its regenerated form byte-exactly. |

## When to Use

- A delivery or verification helper reads git objects through immutable, non-interactive reads (lazy fetch disabled) and fails closed on a partial or fresh clone.
- A verified chain of protocol records binds commit object identifiers from more than one lineage, and at least one lineage was rewritten or force-pushed away.
- A fresh clone of a rewritten branch exists, and historical record carriers still bind the pre-rewrite heads.
- An immutable git read reports `missing object` or a generic query failure although the forge still serves the object.

## Verified Workflow

### Quick Reference

```bash
# Pre-flight: every commit object the whole chain binds must exist locally.
git cat-file -t <oid>          # fails on a missing object
git fetch origin <oid>         # fetch by object identifier restores the
                               # commit and its full ancestry from the forge
```

Enumerate all identifiers, materialize the missing ones, and only then run the
verifier. Do not relax the verifier to make an incomplete source pass.

### Suggested Approach

1. **Enumerate every bound object identifier.** Collect the identifiers from the
   complete record chain, not only the current base and head range. Carriers
   published by earlier sessions or tooling generations can bind lineage heads
   that no branch ref names anymore.
2. **Pre-flight each identifier locally.** `git cat-file -t <oid>` is a cheap
   existence probe. Record the missing set before you touch the network.
3. **Fetch the missing identifiers from the forge.** A fetch by object
   identifier restores the fetched commit and the ancestry behind it. The forge
   keeps recently rewritten objects, so a fetch after a force-push usually
   succeeds; do it before the objects age out.
4. **Regenerate each bound record against the completed source and compare
   bytes.** A record that the verifier regenerates (a manifest, annex, or digest
   block) must match its published form byte-exactly. Do this check yourself
   before delivery; the helper repeats it fail-closed.
5. **Keep the verifier fail-closed.** Helpers disable lazy fetch on purpose:
   an immutable read must not silently fetch and change what it verifies.
   Complete the source instead of enabling lazy fetch or replace-objects on the
   verifier path.

If a fetch by identifier fails, the forge may have pruned the object. Stop and
re-derive the record chain from a source that still holds the objects; do not
fabricate or hand-edit the bound records.

## Failed Attempts

| Attempt | What Was Tried | Why It Failed | Lesson Learned |
| --------- | ---------------- | --------------- | ---------------- |
| Deliver against a fresh clone | Ran the delivery helper with an anchor-source clone that held only the current branch lineage | Every historical carrier bound a pre-rewrite head that the clone did not hold; each immutable git read failed closed | Enumerate all identifiers the whole chain binds and materialize them before delivery |
| Verify only the current range | Verified the current base-to-head range standalone before delivery; it passed | The single-range check exercised only the current lens, not each historical record's own base and head pair | A per-range pass does not prove chain completeness; pre-flight every bound object |
| Re-run the helper after each failure | Retried delivery to rule out a transient fault | The guards are deterministic; an incomplete source reproduces the same rejection | Read the failure as a source-completeness defect, not as a retry case |

## Results & Parameters

### Configuration

```yaml
pre_flight:
  probe: git cat-file -t <oid>          # per object identifier in the chain
  restore: git fetch origin <oid>       # restores commit plus ancestry
  scope: every identifier bound by any record in the verified chain
verifier_environment:                    # what fail-closed helpers set; keep it
  lazy_fetch: disabled                  # GIT_NO_LAZY_FETCH
  replace_objects: disabled             # refs/replace and grafts excluded
  config: isolated                      # system and global config excluded
regeneration_check: byte-exact against the published form, before delivery
```

### Expected Output

- The pre-flight probe passes for every enumerated identifier.
- Each regenerated record matches its published form byte-exactly.
- The delivery or verification run completes without a source-completeness rejection.
